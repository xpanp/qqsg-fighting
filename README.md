# QQ 三国战报 · by ppp

浏览器本地录制与 OCR 工具。用户无需安装 Python 或客户端；模型权重直接从公开 ModelScope 链接下载。录像、识别和本地消息整理都在用户本机完成；开始录制后会自动接入并将识别、合并后的文字同步给 Go 后端；视频与截图不上传。

本仓库提供第二阶段的独立同步、Go 接收/处理和私有管理页面。此前发布版的公开录制页默认不启用上传；原有视频录制和 OCR 仍在本地运行。用户于 2026-11-25 在本地验证完成后追加授权服务器部署，部署与用户验收分开记录。

第二阶段的启动、测试、名单文件、管理员与备份说明见 [本地运行指南](deploy/phase2.md)。需求见 [SPC-0006](docs/spc/0006-server-collection-and-admin.md)，验证及盲区见 [测试记录](docs/tasks/2026-11-24-phase-2-validation.md)。

## 使用

建议使用近期桌面版 Chrome / Edge，通过 HTTPS 打开部署页面。

1. 选择录像保存目录；浏览器要求授权时由用户确认。程序会立即试写并关闭一个小文件，成功后显示“已验证可写”；失败必须重新选目录，不能开始录制。每次开始前再次检查。
2. 选择 QQ 三国的“窗口”，不能选择整个屏幕或浏览器标签页。
3. 在预览画面拖框，框住完整聊天区，建议开启游戏消息时间。
4. 点击“开始录制”。每分钟保存一段 WebM 视频及配套 JSON 时间信息。
5. 默认同时识别文字，可暂停识别而继续录像。下方显示本地合并后的消息，默认每分钟把本会话最新版保存到所选目录，停止时再保存；也可立即保存或手动导出 TXT。
6. 结束时点“停止并保存”，确认最近的视频显示“已保存”，再关闭页面。

开始录制后自动申请并复用本浏览器的采集接入，无需填写来源编号、凭据或区服；页面保留文字去向说明，不显示单独的同步开关。服务器、线路及角色从已授权游戏窗口读取，连续观察确认后展示；未知不影响录像，角色只表示采集视角，不等同用户认证。换线后文字另建逻辑会话，录像继续，已有消息修订仍归原线路。

最多十个近期活跃浏览器来源上传，满额或断网时保留有上限的本地待传队列，自动退避重试。首次接入失败时会保存本次采集意图，停止录像后、重开页面后仍可尝试接入补传；以前未授权的会话不会因此被上传。多个标签页用独立接入锁复用凭据；接入已失效时联系管理员，不自动重新注册绕过撤销。录像始终优先。

录制状态、缓存数据块和最终文件保存是不同状态。“已保存”只在视频与时间文件均关闭提交成功后显示。失败的缓存片段可下载恢复视频及时间信息，较早的未保存片段不会被最近十条记录隐藏。

首次 OCR 从公开 ModelScope 链接下载约 73 MiB 模型，从当前网站下载约 28 MiB 运行库，显示实际下载量、进度及准备阶段，后续按资源校验值缓存。模型下载完仍需校验和启动，页面会分别说明。优先使用 WebGPU，失败时回退 WASM。识别慢不会阻塞录像，但可能漏掉快速滚过的消息。

视频同名 `.json` 是**视频时间说明文件**，记录采集起止时间、选区、会话与片段编号，请和视频一起保留；它不是文字识别结果。文字另外保存为每会话一组 `_messages.txt` 与 `_messages.json`：TXT 可直接阅读，JSON 保留消息 ID、采集时间和修订等信息。每次覆盖为本会话最新完整快照，避免 OCR 纠正后追加重复。两份消息文件并非跨文件原子事务；只有都关闭成功才显示保存成功，失败保留浏览器消息副本供重试。

## 模型来源与服务器流量

网页由自有服务器维护；浏览器直接从固定版本的公开 [ModelScope 模型地址](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.10.0/onnx/PP-OCRv6/rec/PP-OCRv6_rec_medium.onnx) 下载权重，在本机校验 SHA256 和缓存。字典、运行库仍同源提供；不调用在线 OCR，不上传聊天画面。下载来源由生成的 `models/model.json` 的 `url` 指定，没有自有服务器权重下载回退。

用户首次仍需下载约百 MiB，其中约 73 MiB 的模型流量由公开源承担；网站承担网页、字典及约 28 MiB 运行库下载。录像与 OCR 计算仍在本机。首次空页面在开始录制前不注册；本次及已有授权待传记录会产生注册、校时和短间隔文字批次，管理员页面使用鉴权 SSE/查询。服务器不接收视频或图片。

## 开发

需要 Node.js >=22.12 和 npm，不需要 Python。

```powershell
npm ci
npm run prepare:assets
npm run dev
```

打开终端显示的 `/fighting/` 地址。准备脚本生成公开模型 URL、下载并校验字典，运行库来自锁定的 npm 依赖；不下载或打包模型权重。开发依赖可用 `npm ci --registry=https://registry.npmmirror.com` 安装。不要在源码中写入个人路径或密钥。

```powershell
npm test
npm run typecheck
npm run build
npm run preview
```

构建产物在 `dist/`；部署操作见 [deploy/README.md](deploy/README.md)。默认部署到 `https://jinbaofu.cn/fighting/`，保留原首页业务。

## 限制

- 这是辅助记录工具。OCR 仍可能错字、漏字；消息合并不保证完整或准确，也不是游戏服务器的权威事件记录。
- 相同时间、相同位置的近似消息可能无法与 OCR 错读完全区分。算法使用相邻消息顺序、时间和位置保守合并，不按永久全文 Map 去重。
- 页面必须保持开启。后台冻结、电脑休眠、停止共享、关页或浏览器崩溃会中断采集，最后未提交的数据可能丢失。
- IndexedDB 受浏览器配额限制。已确认写入目录的片段会释放视频块缓存；未保存部分保留恢复。清理站点数据会删除本地缓存与消息。
- 文件目录授权通常需要重新选择；网页不能静默访问用户任意目录。恢复视频从第一块按顺序组装，不能把单块当成独立视频。
- 本阶段只保存合并消息和首次/最近来源帧标识、修订摘要，不保存全部原始 OCR 观察；视频是后续离线重处理的依据。
- 自动检查、合成录制和真实窗口长时间录制的验证范围分别记录，未验证条件不能当作稳定性承诺。最终是否符合使用预期由用户验收。
