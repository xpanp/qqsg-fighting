# ADR-0012：独立角色能力与 Admin 原始密码查看

- 状态：已采纳（本地实现，未发布）
- 记录/决策日期：2026-11-28
- 相关 SPC：[SPC-0010](../spc/0010-user-management-and-poc.md)
- 取代/被取代：无
- 记录性质：事前决策

## 背景与选项

用户要求 Admin 与超管分工，并明确允许 Admin 查看普通/超管密码。仅哈希无法还原原文；明文存库便于查看但数据库泄露直接暴露密码；哈希配合受控加密在满足查看需求同时分离登录和解密权限。

## 决策

四角色按显式能力授权，Admin 无超管业务权限，不使用等级继承。新公开账号用户名 4–16、密码 8–18 位；系统内置用户名 admin 符合统一长度规则，由服务器初始化，不开放注册；既有初始化密码继续有效。

普通/超管密码保留登录用的加盐哈希，另存标准 AEAD 密文（Go AES-GCM、随机 nonce、keyId、userId 绑定的关联数据）。加密密钥独立于数据库与 Git，登录不依赖解密。现有 Admin 自身初始化密码仅哈希；既有哈希无法逆向补出原文，不伪造迁移结果。

Admin 通过单独受保护操作按需获取原文（拟 POST 用户密码查看端点；最终路径随接口契约确定）。要求有效 Admin 会话、CSRF、HTTPS、Cache-Control: no-store；用户列表不含原文，页面离开隐藏，不持久化到浏览器。审计仅记录操作者/目标/时间/结果，不记原文，不把接口响应纳入访问日志或监控正文。无密码修改、重置或找回功能。

## 后果与验证

接受持有密钥的服务器可以解密密码的代价，这是用户明确选择的 PoC 功能。密钥需单独保护和备份，数据库备份不能包含明文或内嵌密钥。密钥丢失仍可用哈希登录，但无法查看原文。后续如取消原文查看需新 ADR 并移除密文。

验证四角色直接接口调用、Admin 专属查看及 CSRF/缓存/日志保护；覆盖长度边界与旧 Admin 登录。账号权限及密码查看的本地验证记录见 SPC-0010。
