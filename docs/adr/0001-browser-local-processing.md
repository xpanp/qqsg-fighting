# ADR-0001：浏览器本地处理与前后端同仓

- 状态：已采纳（历史补录）。
- 记录日期：2026-11-24；原选择发生于第一阶段设计与 2026-11-21 实施期间。
- 关联：[SPC-0001](../spc/0001-browser-local-capture.md)、[现行架构](../architecture.md)。
- 取代/被取代：无；权重分发的后续选择见 ADR-0004。

## 背景与选项

伙伴应只需浏览器，无需安装 Python。当前先做好本地采集，后续才接 Go 服务、多用户与战报。

| 选项 | 收益 | 成本 |
| --- | --- | --- |
| 桌面 Python 程序 | 可复用原流程 | 打包、分发及运行环境维护 |
| 上传视频、服务器 OCR | 用户端算力要求低 | 视频上传、服务器算力和隐私成本 |
| 浏览器本地录制与 OCR | 无安装，计算留本机 | 浏览器 API、权限、硬件和后台运行限制 |

## 决策

采用 TypeScript + Vite 的模块化静态前端，本机 WebGPU 优先、WASM 回退；录制与识别独立。前端与后续 Go 服务同仓，通过 contracts 预留数据边界，第一阶段不建立空业务服务或假上传实现。

## 后果与验证

服务器当前不接收视频或文字。必须如实处理窗口/目录授权、资源加载与后台暂停；关页不能承诺连续采集。未来同步须另建 SPC/ADR，不能假设已有登录、设备身份或多人合并协议。
