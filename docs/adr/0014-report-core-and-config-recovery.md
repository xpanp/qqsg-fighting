# ADR-0014：复用 Go 报表核心与可恢复的版本化配置

- 状态：已采纳（本地实现，未发布）
- 记录/决策日期：2026-11-28
- 相关 SPC：[SPC-0010](../spc/0010-user-management-and-poc.md)
- 取代/被取代：无；扩展 ADR-0007，不替换已有原始数据与投影分离
- 记录性质：事前决策

## 背景与选项

单独复制离线统计会使名单、去重和报表口径漂移；CLI 直接调用线上 HTTP 或读取生产数据库又失去离线能力。名单覆盖写入无法审计恢复，重算竞争可能发布过期结果。

## 决策

维持 Go 模块化单体。共享不依赖 HTTP/SQL 的解析、事件处理、归一化、统计与导出核心；应用层编排，HTTP/SQLite/文件为适配器。保留当前 qqsg-server 无子命令兼容入口，增加 server/report。CLI 使用显式输入文件与输出路径，无需启动服务或读取服务用户数据库。

输入时间需有日期、时区及来源依据，多视角保留自身角色映射；不能用重跑日期替代游戏日期，不能对混合视角统一替换“你”。名单 A/B/others、别称及黑名单使用现有格式的显式适配，不嵌入真实名单。服务端和 CLI 对相同输入、配置/算法版本产生同口径统计与异常记录。

沿用 SQLite 既有配置快照，每次变更完整留存并记录操作者。恢复创建新版本及 restoredFrom；显示版本单调递增，既有内部 ID 可保留。事务切换后异步重算，结果发布比较配置版本和输入代次，过期任务不得覆盖。查询与导出绑定已发布投影版本；失败保留一致的旧结果并提示状态。

每日用 SQLite VACUUM INTO 一致性快照 写独立运行目录，默认保留 30 份日备份；部署前备份单独管理。PoC 名单历史全部保留，加密密钥独立受保护备份；自动异机备份本轮不实现。

## 后果与验证

避免复制处理规则和引入微服务；需要清晰的输入契约、重算代次及输出版本。覆盖历史多视角回放、服务/CLI金样一致性、黑名单与 A/B 互战口径、恢复并发、过期任务、重算失败以及数据库/密钥恢复演练。已执行的验证及待验证事项见 SPC-0010。
