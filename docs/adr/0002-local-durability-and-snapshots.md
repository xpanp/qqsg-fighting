# ADR-0002：视频先暂存再落盘，消息保存修订快照

- 状态：已采纳（历史补录）。
- 记录日期：2026-11-24；原实现分布于 2026-11-21—22。
- 关联：[SPC-0001](../spc/0001-browser-local-capture.md)、[SPC-0002](../spc/0002-preparation-and-message-files.md)。
- 取代/被取代：无。

## 背景与选项

录制可能被中断，用户不能只依靠最后关闭时的一次保存；OCR 又会多次修订同一消息。

| 选项 | 收益 | 成本 |
| --- | --- | --- |
| 所有视频留内存，结束时保存 | 实现简单 | 内存与异常丢失风险 |
| 数据块暂存，分段写用户目录 | 可恢复已提交部分，分段确认 | 配额、异步生命周期、恢复与并发控制 |
| 消息只追加文本 | 写入简单 | 修订产生重复，难以表达最终结果 |
| 每会话保存最新消息快照 | 稳定 ID 的修订能覆盖 | 定期重写，文件大小随会话增长 |

## 决策

视频块先写 IndexedDB，按实际时间分段，视频和时间 JSON 都关闭成功后才报“已保存”并释放对应块缓存。失败块保留恢复入口，录制/恢复通过 Web Locks 互斥。

消息保留浏览器副本，默认每分钟及停止时将本会话最新 TXT/JSON 快照串行写入所选目录，无变化不重写；写入失败保留可重试状态，不阻塞录像。

## 后果与验证

未提交尾部仍可能丢失；清理站点数据会删除浏览器副本。两个文件不是跨文件原子事务，部分成功仍必须标为未全部保存。长会话文件增长、目录授权失效及配额问题需要继续验收。

依据：[初版验证](../tasks/2026-11-21-validation.md)、[快照验证](../tasks/2026-11-22-validation.md)；原测试与 OPFS 写入不代表断电零丢失或真实目录授权全通过。选项为事后整理。
