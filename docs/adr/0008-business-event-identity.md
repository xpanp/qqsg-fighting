# ADR-0008：将上传幂等与击杀事件身份分开

- 状态：已采纳；实现及本地回归，生产验收另行记录。
- 记录/决策日期：2026-11-25。
- 关联：[SPC-0006](../spc/0006-server-collection-and-admin.md)、[ADR-0006](0006-durable-message-sync.md)。
- 性质：实施中决策，来源为真实双视角回放及独立 Review；细化 ADR-0006，不改变录制。

## 背景与选项

6,240 条既有消息回放证明：一个来源也可能给同一次游戏播报分配多个本地消息 ID。按 source/session/message/revision 接收幂等能避免重传，无法消除这些业务重复。中间版本有 3,999 条有效 A/B 记录，但发生秒与标准双方的唯一组合仅 2,983 个；旧 Python 的 3,003 也不是权威真值，不能为了贴合旧数调整规则。

| 方案 | 收益 | 风险 |
| --- | --- | --- |
| 只按消息 ID 幂等 | 精确保留上传 | 不同 ID 的同一播报重复计数 |
| 同一死者三秒内都删除 | 数量变少 | 吞掉不同真实事件，缺乏证据 |
| 游戏时间、上下文及双方一致时关联证据 | 区分传输与业务身份，可追溯 | 游戏钟只有秒精度，仍需人工拆分入口 |

## 决策

采用第三项。区服/线路已知、推断出的完整日期及有效游戏 HH:mm:ss 相同、标准双方均已确定且相同时，允许同源不同消息 ID 或不同来源关联为同一次击杀。不同双方、不同游戏时间/日期、不同上下文都保留。只有观察时间或人名尚未确定时，不自动建立新的跨消息关联。

原始上传和修订全部保留，`sourceCount` 是不同来源数，不是收到的消息条数。显式拆分和已有人工决定优先，不能静默吞掉彼此冲突的人工调整。算法版本更新触发全量重算，名单匹配沿用旧流程的标点比较、唯一缺字候选及装饰字形比较，不硬编码具体人名。

原始来源归属 `Members/event_links` 与人工合并展示 `Sources` 分开。展示可以汇集多个事件的证据，但不能因此重绑来源的稳定身份；管理员合并拒绝循环，提供 reset 撤销并留下审计。增量重算需要把人工关联的成员闭包一起读入。

## 验证与限制

保留真实不同游戏时间的同源两次击杀、同秒不同双方；新增同秒同双方的同源重复专项，修正旧测试把“第二次真实击杀”错误设置为相同游戏时间的假设。覆盖合并、两次全量重算、来源修订、循环拒绝及撤销，不能仅证明统计数字变小。

日期仍由观察日期和跨午夜规则推断，不保证识别错误或历史超过一天的停留消息都能准确定日。相同双方在同一游戏秒真实发生两次的极端情形可由管理员拆分，不宣称服务器权威精度。
