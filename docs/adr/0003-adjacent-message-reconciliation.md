# ADR-0003：按相邻视口对齐与修订消息

- 状态：已采纳（历史补录）。
- 记录日期：2026-11-24；依据第一阶段实现及后续缺陷记录补录。
- 关联：[SPC-0001](../spc/0001-browser-local-capture.md)、[SPC-0004](../spc/0004-compact-chat-segmentation.md)。
- 取代/被取代：无。

## 背景与选项

聊天画面会静止、滚动和换行；OCR 对同一条消息可能识别不同。真正的新消息也可能与旧消息完全相同。

| 选项 | 收益 | 代价 |
| --- | --- | --- |
| 每帧全部作为新消息 | 不需要对齐 | 大量重复 |
| 永久按完整文本去重 | 易实现 | 吞掉真实重复，错字仍会新增 |
| 相邻有序视口对齐与投票 | 利用滚动重叠，支持纠正 | 存在歧义，需要上下文和回归样本 |

## 决策

消息合并是独立于 OCR、存储与后续击杀提取的模块。按相邻视口顺序匹配，模糊匹配需要邻居或明确游戏时间与位置证据。同一消息保持 ID，以 revision 表示文字更新；相同内容离开视口后再次出现可产生新事件。现阶段仅持久化合并结果及首末来源摘要，不宣称保留全部原始 OCR 观察。

频道边界用于拼接换行；当前实现仍可能因频道缺失或错误而无法整理消息。不能把这项实现局限理解成永远丢弃可读文字的产品目标，后续改进需对应规格和回归。

## 后果与验证

同秒、同位置、近似文本仍可能难以区分；不能声称权威战绩。分行修复属于此流水线的实现纠错，无需为每个阈值新建 ADR。依据：[消息/录制原验证](../tasks/2026-11-21-validation.md)、[小框修复记录](../tasks/2026-11-22-chat-delay.md)。
