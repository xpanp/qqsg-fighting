# ADR-0005：SPC 与 ADR 分目录维护

- 状态：已采纳。
- 记录/决策日期：2026-11-24。
- 来源：用户本次明确确认的目录与文档职责。
- 关联：[SPC-0005](../spc/0005-documentation-structure.md)。
- 取代/被取代：取代新增需求继续只堆日期任务文件的文档组织方式；保留原文件作历史证据。

## 背景与选项

已有任务、规格、验证与架构理由混在日期文件中，难以分清当前状态、需求边界和选择原因。

| 选项 | 收益 | 代价 |
| --- | --- | --- |
| 继续所有内容放日期任务文件 | 无迁移成本 | 需求与决策难检索，状态易过时 |
| 每迭代目录固定放 SPC.md/ADR.md | 迭代内容集中 | 容易为空决策造文件、跨迭代决策重复 |
| SPC/ADR 各自独立目录和编号 | 职责明确，可跨需求引用决策 | 需要维护关联索引 |

## 决策

采用根目录 AGENTS.md、README.md，docs/architecture.md 维护当前架构，docs/spc/ 每需求一份规格，docs/adr/ 每重要决策一份记录。一个规格关联零个或多个决策；无新决策写明沿用记录，不建空 ADR。模板位于 docs/templates/，总入口为 docs/README.md。

## 后果与验证

SPC 先于实施建立；重要决策在实施前记录并在落地后更新。已采纳决策被改变时新增 ADR 并维护取代关系，不覆盖历史。早期内容事后补录并明确来源，用户验收不能由代码审查或部署状态代替。

验收为文档可导航、编号与状态一致、链接有效、无历史验收伪造；本次不改业务代码或重新部署。
