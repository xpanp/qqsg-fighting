## 录制与同步故障验证

确认 `capture/recorder.ts` 与此前 HEAD 文本一致。只增加有界的消息分页读取，未升级录像数据库。上传在本地消息保存之后非阻塞通知，网络不进入录像/推理等待链。

覆盖断网、请求挂起、校时与真实 ingest 阶段 HTTP 500/401、部分确认、错误批次/外来/重复确认、确认与新修订竞态、永久/临时拒绝、来源切换、未授权历史不补传、停止取消、缓存满和恢复。明确输出 `retryable:false`，防止永久拒绝误变成无限重试；UI 待上传数与实际未确认记录一致。

实际采集时间由 Date.now 与单调时钟相加，可能有小数；wire int64 边界仅在序列化时四舍五入 UTC 毫秒，保留本地原始时间。新增专项验证，另用真实 Go JSON 接口验证整数约定和永久拒绝字段。

默认队列为 5,000 条、单条文字最多 4,000 字符，回执最多 100,000、授权会话最多 1,000；30 天以上无待处理记录的会话清理同步元数据，原本地文本不删。上限表示暂停/提示，不能当作无限运行承诺。独立压力测试**自定义 limit=10,000**，约 2 秒入库，第 10,001 条拒绝而保留已有数据；单次最多读取/上传 50 条，不把整个积压搬到主线程。

合成并行测试运行真正 DurableRecorder 与 SyncClient，用模拟编码器及文件句柄：上传永久挂起期间以 15ms 分段运行，至少三段完成 append/finish/write，停止提交末段，未确认文字继续保留。这证明调度隔离，不证明实际视频可播放或一小时真窗口稳定。
