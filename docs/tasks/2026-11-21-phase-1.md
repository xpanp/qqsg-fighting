# 第一阶段：浏览器本地采集产品化与部署

建立日期：2026-11-21。状态：代码实现及独立审查完成，发布与用户验收中。

架构依据：[architecture.md](../architecture.md)。本文件是开发与验收清单，不是完成报告。

## 目标与范围

普通用户从 HTTPS 网页进入，选择本地目录、共享 QQ 三国窗口并框选聊天区，即可录制和在本机识别；页面只展示本地合并后的原始消息，不展示内部测试面板。

包含：本地录像、时间元数据、本地 PP-OCRv6、跨帧消息合并、本地消息展示、错误状态与恢复，以及现有服务器上的静态部署。

不包含：登录、业务后端、数据上传、多人去重、人名/阵营归一化、击杀解析、统计和 Excel。保留未来接口约定，不实现或启用以上功能。

## 最终交付目标

本阶段必须完成“架构符合需求 → 独立测试与代码审查通过 → 本阶段成果整理为一个 commit 并推送 GitHub → 实际部署至用户服务器 → 用户验收”的完整闭环。不能只交付本地 Demo、部署脚本或口头部署方案。

用户已明确授权本阶段最终提交、推送和部署。开发中不按每次修补零碎提交；最终检查本阶段全部改动，包括已有验证代码，仅纳入必要且经过审核的内容。不改写既有共享历史，不擅自强推。部署应使用最终提交对应的构建产物。

实际部署后由用户验收。在用户明确验收通过之前，状态为“已部署，等待用户验收”，不等同于本阶段已被用户接受。

## 当前基础

原技术验证资料已归档到本机 .tools/legacy-demo，不提交 Git。当前模块化实现位于 frontend/；验证证据见 [本阶段验证记录](2026-11-21-validation.md)。

## 人工验收记录（待执行）

记录日期、浏览器版本、GPU/CPU 路径、样本、实际结果和证据路径。至少覆盖：

- Chrome 与 Edge：真实共享窗口、强制框选、取消授权、正常开始/停止、切换窗口或重选区域的行为。
- 连续真实录制至少 60 分钟：逐段检查视频可播放、时间与片段顺序；记录切段间隙/重叠，不只检查文件数量。
- 前台与后台分别测试；最小化、电脑休眠、窗口关闭、共享停止和页面刷新时的状态与恢复边界如实记录。
- 保存成功、写入失败、授权被撤销、配额/空间不足：不得显示虚假“已保存”；测试使用隔离目录与替身故障注入，不填满用户磁盘。
- OCR 慢速/异常：录像继续，采样队列有界；无 GPU 的浏览器给出实际可用性结论。
- 消息合并：静止重复、滚动重叠、连续快刷、上下截断、近似错字、相同内容真实再次出现。
- 从部署后的 HTTPS 页面验证完整流程，开发服务器成功不能代替部署验收。
- 网络检查：只有静态网页、模型与运行库下载，无录像、截图、OCR 或消息上传。
