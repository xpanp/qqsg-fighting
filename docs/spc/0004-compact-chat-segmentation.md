## 问题与范围

资源已经就绪、页面持续识别，却要等几十秒才看到一条消息。实际 516×126 选区的背景纹理把多行连接成大块，再被边缘规则过滤。

本轮修正亮字行投影、缩小严格边缘检查范围，增加设备、逐行进度及空结果原因。无需更换模型、为人物硬写规则或调整频道/人名提取。输入仍保留原 RGB。

## 验收与任务

| 验收项 | 原结果 |
| --- | --- |
| 实际小框可提取正常行，不把整窗当作一行 | 四帧旧行数 0/0/1/0，修复后 5/5/5/3 |
| 首帧能产出消息，而非等到画面恰好满足旧规则 | 首帧实际 GPU 约 1129ms，整理 3 条；后续约 333—510ms |
| 多色亮字、纹理背景、完整首末行和残片处理 | 新增合成回归，原总计 68 项通过 |
| 设备、处理进度、读到文字与新增消息分开解释 | UI 与 Review；推理快不代表已读到全部文字 |
