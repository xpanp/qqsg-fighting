# SPC-0006：多人文字收集与管理员实时战报

- 建立日期：2026-11-24。
- 状态：本地实现与自动验证完成；待用户验收。用户于 2026-11-25 先要求仅本地，随后追加明确授权部署服务器；生产发布检查单独记录。
- 来源：用户要求保持公开录制稳定，增加 Go 收集、多人合并和仅 admin 可访问的战报与统计。
- 负责人：协调者统筹；实施时分配前端、后端、架构、产品、独立测试与 Review。
- 相关决策：[ADR-0006](../adr/0006-durable-message-sync.md)、[ADR-0007](../adr/0007-server-processing-and-admin.md)；业务身份细化见 [ADR-0008](../adr/0008-business-event-identity.md)。沿用 ADR-0001—0004 的本地采集、保存及模型边界。

## 目标与非目标

现有公开页面继续选窗口、框选、录制、运行本地 OCR 和合并消息。新增独立文字同步，把多人看到的系统播报汇集到 Go 后端；管理员实时查看击杀及统计，并能事后调整配置、纠错和重算。

本轮包含一个 admin、采集来源标识和接入凭据，不要求普通用户注册。不上传视频、截图或全量逐帧 OCR；上传本地合并消息及其修订。第一阶段已有视频与消息文件保存继续保留。

不做完整用户系统、复杂权限、多服分布式部署、服务器 OCR、视频托管或自动判定战斗开始/结束。预留用户归属及战斗场次，不用空实现假装已具备能力。

## 采集与同步

- 录制链路不依赖网络、Go 服务或管理员登录。上传调度不进入 MediaRecorder 回调或 OCR 推理的等待链。
- 合并消息本地提交后，按稳定消息 ID 和 revision 进入持久待上传队列；保留本地写入与入队的一致性，重启可扫描补入未确认修订。
- 未配置/未授权的公开页面默认关闭文字同步；用户配置接入并勾选后才启用。明确告知文字上传范围及用途，提供暂停入口；暂停不影响录像和本地结果。
- 短间隔小批量发送，逐项确认成功后才出队；超时、重复发送、乱序及响应丢失均可恢复。认证失败进入需处理状态，不无限快速重试。
- 队列有可配置数量/空间上限；接近上限时提示。达到上限暂停新增同步、标记缺口并保留已有队列，不挤占录像缓存，不无提示丢弃。单独存储仍共享浏览器磁盘配额，不能承诺绝对隔离。
- 普通页面只显示同步开关、待上传数、最近成功及异常；管理页面不出现在导航。旧版页面不自动刷新或强迫停止当前录像。

## 时间、接收与多人合并

分别保存采集 UTC 时间、会话单调相对时间、原始游戏时间、服务器接收时间，以及可估计的时钟偏差和不确定性。提供轻量校时请求；网络往返中点只能估计偏差。游戏时间缺日期、跨午夜或客户端时间错误时保留证据及待确认状态，不用接收时间覆盖发生时间。

服务端处理按以下层次分开：

1. **接收幂等**：来源、会话、消息 ID、revision 唯一；事务提交后确认。旧修订迟到不覆盖新修订，同键不同内容隔离记录冲突。
2. **跨来源合并**：候选按事件时间区间、频道、游戏时间、上下文及文本相似度对齐，保留每条来源关联。缺少可靠时间时保守标记，不强制合并。
3. **击杀提取**：识别频道边界及换行，只从地图频道提取完整“甲在战斗中击败了乙”；保留无法解析或疑似跨行污染的消息，排除统计并说明原因。
4. **人名归一化**：应用标准名单、显式别名和可解释相似度匹配；标点清理只用于匹配，不改变展示原名。多候选、低置信度进入待确认，不能为凑人数强行合并。
5. **统计投影**：由计入事件生成可重算结果，关联配置版本与算法版本；新修订、管理员更正及重算可以撤销旧计数，不能只做累加。

时间戳不是唯一去重键。同秒不同击杀均保留；短时间同一死者是疑似重复证据而非绝对规则，击杀者连续击杀不同人必须保留。相同文本间隔后再次出现可是真实新事件。支持迟到上传和历史修订，不能仅看“最近已收到几秒”。

实施中的真实回放进一步明确：同区服/线路、同完整游戏发生秒、同确定标准双方的不同消息 ID 可关联为一次事件，包括同源重复；不同双方/日期/游戏时间不合并。缺游戏时间或人名未确定时不新建自动关联，只有观察时间的事件明确标为近似且发生时间误差未知。人工拆分/决定优先，原始修订永远保留，详见 ADR-0008。

现有 Python 脚本作为处理行为参考，实施前盘点实际有效脚本和名单，使用脱敏样例建立 Go 对照用例；不承诺直接逐行翻译后效果相同。

## 配置与管理员页面

服务端名单使用通用 `name_a.txt`、`name_b.txt`、`name_others.txt`，一行一个标准名；另有 `aliases.tsv`（标准名与别名）、`blacklist.txt`。真实名单不提交 Git。跨阵营重名/别名冲突必须报告，不能按文件读取顺序决定。未匹配角色归 others 并保留待确认标识。

管理员修改经校验后生成不可变配置版本，运行配置可原子切换；保留变更记录、旧版本及重算范围。不得直接改历史原文。黑名单匹配标准名和归一化后的别名；任一方命中则整条事件排除所有统计，原始记录仍可查询。

管理入口规划为 `/fighting/admin/`，以下两个业务页面均需登录：

- **击杀战报**：实时更新、时间筛选、原始合并播报与解析双方、来源数、状态/原因；可查看来源文本、关联/拆分疑似重复、修正人名或计入状态，修正有审计。
- **战报统计**：默认最近三小时滚动窗口，也可指定历史起止时间。展示战斗概览、击杀表、死亡表、KDA（无助攻数据，只展示 K/D，不伪造 A）、阵营人数/人头占比及优势最大的十分钟窗口；沿用既有用户要求，互杀统计仅计 A/B 对抗，others 不进入双方概览。两张人员表都带阵营，明细对象次数可展开。零死亡显示无死亡及原始 K/D，避免除零；统计区间统一左闭右开。

参战人数指所选区间有效 A/B 事件中出现的不同标准角色数，不代表在线总人数。十分钟优势默认以 A/B 击杀净差衡量，分别展示 A、B 最优窗口、实际区间和计数；不足十分钟标明覆盖时长，完整公式及确定性并列规则写入实现契约并用样例验收。

支持导出所选区间 Excel：概览、击杀、死亡、K/D、阵营及带时间的事件数据。导出与页面共享同一版本、筛选及排除规则。重算期间展示当前已发布版本和进度，新版本完成后整体切换，避免混合新旧统计。

## 身份与访问

只配置一个 admin，不开放注册。密码通过部署命令初始化，不放源码、网页或明文配置；使用适当的密码哈希、服务端会话、Secure/HttpOnly/SameSite Cookie、登录限流及写操作 CSRF 防护。未登录者访问所有管理查询、推送、修改与导出都被拒绝，隐藏路径不代替鉴权。

采集端使用独立、可撤销的接入凭据，只能上传自己的来源和读取必要校时信息，不能读取他人消息或管理配置。凭据由管理员生成并私下分发/导入，不内嵌公开 JS；这是采集授权，不是完整用户账户。来源 ID 是来源标签，不是可信实名。接口校验大小、数量、速率，错误不回传其他用户原文；服务日志避免记录令牌及完整聊天。

## 数据与部署规划

具体目录、数据生命周期及部署边界见 [第二阶段设计](../phase-2-design.md)。当前静态站点继续可用；先部署后端和管理入口，再以功能开关小范围启用上传。录制期间不强制刷新。关闭同步可回到本地模式；后端故障不得使静态采集页不可访问。

本轮不默认删除历史数据。保存策略和备份必须可配置、可检查；原始文字、来源、修订和审计是重算依据，不能当临时缓存清掉。定期备份数据库及匹配版本的名单/配置；恢复验证属于交付检查。

## 交付记录

本地实现与测试见 [验证记录](../tasks/2026-11-24-phase-2-validation.md)，启动见 [本地运行说明](../../deploy/phase2.md)。2026-11-25 用户明确“不部署到服务器，本地做完验证即可”；本轮不推送、不部署，不改现网。用户验收、实际窗口一小时、多人在线和生产恢复均未完成。时钟精度、OCR 错字、浏览器配额和后台冻结仍有限制，不承诺绝对完整或零丢失。
